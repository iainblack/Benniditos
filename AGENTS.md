# Bennidito's website

Marketing site for Bennidito's Pizza & BrewPub (two locations in Spokane, WA).
Live at https://www.benniditos.com.

## Stack

- Next.js 13.2 **Pages Router** (`pages/`), React 18, TypeScript. No App Router.
- MUI v5 for UI (`@mui/material`, styled with Emotion). Theme in `Theme.ts`.
- Menu and tap-list content: Firebase Realtime Database, with bundled JSON fallbacks.
- Google Maps JS API via `@react-google-maps/api` for the delivery map.
- Hosted on Vercel, with `@vercel/analytics` in `pages/_app.tsx`.

## Commands

```bash
npm ci                              # install (use ci; the lockfile is authoritative)
npm run dev                         # http://localhost:3000
npm run build                       # production build; also type-checks
npm run lint                        # next lint
npx tsc --noEmit                    # standalone type-check
npm run generate:delivery-area      # rebuild src/assets/deliveryArea.ts from the KML
```

There is no test suite. Verify changes by running `npm run build` and loading the
affected pages in a browser, checking the console for errors.

## Environment

Copy `.env.example` to `.env.local`. Only two variables are used on `main`:
`NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` and `NEXT_PUBLIC_FIREBASE_APIKEY`. Production
values live in Vercel (`vercel env pull`). The project is linked in `.vercel/`.

## Layout

- `pages/index.tsx`: homepage, built as a stack of panels from `src/components/Panels/`
  (Title, SlideShow, SouthHill, BrewPub, Delivery, Reservations, Footer).
- `pages/BenniditosMenu.tsx`, `pages/BrewPubMenu.tsx`, `pages/OnTap.tsx`: menu pages.
  Each renders bundled JSON from `src/utils/*Data.json` immediately, then replaces it
  with the Firebase Realtime Database node (`SouthHill`, `BrewPub`, `TapList`).
  **Editing the JSON alone does not change what production shows** while Firebase has data.
- `src/components/Products/`: menu section renderers. `src/utils/utils.tsx` holds shared
  types (`BenniditosMenuConfig`, `TapListConfig`) and helpers.
- `src/components/ErrorBoundary.tsx`: reusable boundary. Wrap third-party widgets in it.
- `fonts/`: local font files. `public/`: images (some filenames contain spaces).

## Delivery map (`src/components/Panels/DeliveryPanel.tsx`)

- The delivery area is a polygon whose source of truth is `src/assets/ditos.kml`.
  `src/assets/deliveryArea.ts` is **generated** from it: edit the KML, then run
  `npm run generate:delivery-area`. Don't hand-edit the `.ts` file.
- The "do we deliver here?" check uses `google.maps.geometry.poly.containsLocation`
  against the polygon. That's the real outline, not its bounding box.
- The map is isolated in `DeliveryMap`, wrapped in `ErrorBoundary`, and shows a
  `MapUnavailable` fallback on load errors. Maps API callbacks (geocoder, autocomplete)
  are wrapped in try/catch because error boundaries don't catch async errors. Keep
  this pattern for any new Maps code.
- The Maps API is pinned to the `quarterly` channel in `useLoadScript`.

### Incident history

In Oct 2026 production showed "A client-side exception has occurred" on the homepage.
Google removed `KmlLayer` from the Maps JS API (v3.66), the site loaded the `weekly`
channel, and the uncaught error crashed the whole page. The fix replaced `KmlLayer`
with a native `Polygon` from bundled coordinates, added the error boundary, and pinned
`quarterly`. Lesson: third-party scripts can break with no deploy on our side, so
contain them so one widget can't take down the page.

## Conventions and gotchas

- Imports use the `@/` alias for the repo root (e.g. `@/src/components/...`).
- MUI's Emotion peers (`@emotion/react`, `@emotion/styled`) must stay in
  `dependencies`. They were once missing, and builds only worked because of Vercel's cache.
- `reactStrictMode` is on, so effects run twice in dev. Effects that create Maps
  objects must return a cleanup function.
- `next lint` currently reports one pre-existing warning in `src/components/imageSlider.tsx`.
- The homepage requests `/undefined` (404) on load. This is pre-existing and harmless
  but unexplained.
- The online-order URL is not consistent: most places use `https://benniditos.weborder.net/`,
  but `SouthHillPanel.tsx` still links to `weborder7.microworks.com`. Check with the owner
  before changing it.

## Deployment and git

- Pushing to `main` deploys to **production** on Vercel (benniditos.com). Other
  branches get preview deployments. Confirm with the user before pushing `main`.
- Always ask before committing or pushing.
- `sanity-migration` is a long-running branch that moves menu content to Sanity CMS and
  upgrades to Next.js 16. It has different dependencies, so run `npm ci` after switching
  branches. It also has its own `AGENTS.md` block generated by `next dev`; when merging,
  keep both sections.
- GitHub repo: `iainblack/Benniditos` (the old `benniditoa` remote URL redirects).
